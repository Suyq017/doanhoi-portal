# Tóm tắt Implementation Ollama và Kế hoạch Phase tiếp theo

## Giai đoạn 1: Tích hợp Ollama vào Backend (Đã hoàn thành)

Trong giai đoạn đầu tiên, chúng tôi đã hoàn tất việc tích hợp Ollama như một giải pháp thay thế cho Gemini trong hệ thống RAG chatbot. Dựa trên file ollama_model.md, hệ thống hiện có khả năng chuyển đổi linh hoạt giữa hai models: Gemini (sử dụng embeddings 768 chiều và model gemini-2.0-flash) và Ollama (sử dụng BGE-M3 embeddings 1024 chiều kết hợp với Qwen2.5:7b LLM chạy local).

Về mặt cơ sở hạ tầng, chúng tôi đã cài đặt các dependencies cần thiết bao gồm @langchain/ollama và @langchain/community, đồng thời cấu hình environment variables để hỗ trợ việc toggle giữa hai models thông qua biến USE_LOCAL_MODEL. Các npm scripts như models:check, models:migrate và models:health cũng đã được tạo ra để hỗ trợ việc kiểm tra và quản lý models.

Kiến trúc services đã được thiết kế với hai services chính là UniversalEmbeddingsService và UniversalLLMService, cho phép hệ thống tự động chuyển đổi giữa Gemini và Ollama dựa trên cấu hình. Các services LangChain hiện có như Vector Store và Chat Service đều đã được refactor để tương thích với kiến trúc mới này. Health check endpoints cũng đã được implement để monitoring trạng thái của các models.

Ngoài ra, chúng tôi đã xây dựng các utility scripts quan trọng. Script check-model-status.ts giúp kiểm tra model đang được sử dụng và trạng thái kết nối, trong khi migrate-embeddings.ts hỗ trợ việc re-ingestion dữ liệu khi cần chuyển đổi giữa các models có dimension khác nhau. File package.json cũng đã được làm sạch để loại bỏ các scripts trùng lắp và tối ưu hóa workflow.

## Giai đoạn 2: Phát triển Frontend và LLM-as-a-Judge (Kế hoạch)

Giai đoạn tiếp theo sẽ tập trung vào hai mục tiêu chính: xây dựng giao diện chat frontend và triển khai hệ thống đánh giá tự động sử dụng kỹ thuật LLM-as-a-Judge. Về phần giao diện, chúng tôi sẽ phát triển một chat widget hiện đại với khả năng hiển thị dưới dạng widget nhỏ hoặc full-page view. Giao diện này sẽ hỗ trợ real-time streaming responses để người dùng có thể thấy câu trả lời được generate từng phần, tạo trải nghiệm mượt mà hơn. Message history sẽ được implement với scroll virtualization để tối ưu performance khi có nhiều tin nhắn. Các tính năng phụ trợ như typing indicators, markdown rendering, và có thể mở rộng thêm file attachments cũng như voice input sẽ được cân nhắc.

Tech stack cho frontend sẽ sử dụng React với TypeScript để đảm bảo type safety, kết hợp với TailwindCSS hoặc Material-UI cho styling. WebSocket hoặc Server-Sent Events sẽ được sử dụng cho streaming responses, và React Query sẽ giúp quản lý state một cách hiệu quả. Giao diện cần đảm bảo responsive trên cả mobile và desktop, đồng thời tuân thủ các chuẩn accessibility WCAG 2.1.

Về hệ thống LLM-as-a-Judge, đây là một component quan trọng để tự động đánh giá chất lượng responses từ chatbot. Kiến trúc hoạt động theo luồng: khi user gửi query và RAG system generate response, một LLM judge (có thể là Gemini hoặc Ollama) sẽ tự động đánh giá response đó dựa trên nhiều tiêu chí. Các tiêu chí đánh giá bao gồm Relevance (response có trả lời đúng câu hỏi không), Accuracy (thông tin có chính xác với context không), Completeness (response có đầy đủ thông tin không), Clarity (response có dễ hiểu không), và quan trọng nhất là Hallucination Detection để phát hiện xem chatbot có bịa đặt thông tin không có trong context hay không.

Backend sẽ cần implement một LLMJudgeService mới để xử lý logic đánh giá, kèm theo EvaluationEntity để lưu trữ kết quả đánh giá vào database. Database schema sẽ bao gồm các trường như conversation_id, response_id, các scores cho từng tiêu chí, has_hallucination flag, judge_reasoning để giải thích lý do đánh giá, và judge_model để biết đang dùng Gemini hay Ollama làm judge. EvaluationController sẽ expose các API endpoints để frontend có thể query và hiển thị kết quả đánh giá.

Phần frontend của evaluation system sẽ hiển thị rating scores ngay trong chat UI để người dùng có thể thấy chatbot đang perform như thế nào. Một admin dashboard riêng sẽ được xây dựng để xem analytics tổng quan, bao gồm các metrics như average evaluation scores theo thời gian, response time distribution, user satisfaction trends, common query patterns, hallucination rate, và so sánh performance giữa Gemini và Ollama. Dashboard sẽ sử dụng các visualization như line charts, bar charts, heatmaps để trực quan hóa dữ liệu, và có chức năng export reports cho việc phân tích sâu hơn.

Về timeline implementation, chúng tôi dự kiến chia thành 5 tuần. Tuần 1-2 sẽ tập trung vào frontend chat UI, từ việc design component architecture, implement basic chat với messages và input, tích hợp streaming, thêm markdown rendering, đến responsive design và unit tests. Tuần 3 sẽ dành cho LLM Judge backend, bao gồm design evaluation schema, tạo LLMJudgeService với evaluation prompts, implement scoring logic, và tích hợp vào chat flow. Tuần 4 sẽ xây dựng analytics và dashboard với các queries tối ưu, visualization charts, và export functionality. Tuần 5 dành cho testing tổng thể, bao gồm end-to-end testing, load testing với concurrent users, A/B testing để so sánh Gemini và Ollama judges, cùng performance optimization và documentation.

Về technical decisions, chúng tôi recommend sử dụng React với TypeScript cho frontend nhờ khả năng reusability và strong typing. Streaming protocol sẽ ưu tiên Server-Sent Events vì đơn giản hơn WebSocket nhưng vẫn đáp ứng đủ nhu cầu với auto-reconnection và HTTP/2 multiplexing. LLM Judge sẽ thiết kế dual-mode tương tự RAG system, cho phép toggle giữa Gemini (development) và Ollama (production) thông qua biến USE_LOCAL_JUDGE. Evaluation data sẽ lưu trong PostgreSQL hiện có, tận dụng JSONB cho flexible metadata và indexes cho query performance.

Success metrics cho Phase 2 bao gồm: UI phải đạt response time dưới 2 giây với mobile usability trên 95%, Judge accuracy cần đạt trên 85% agreement với human evaluation, hệ thống phải support được 100+ concurrent users, evaluation coverage cần trên 90% responses, và dashboard phải có real-time updates với latency dưới 5 giây. Những metrics này sẽ giúp đảm bảo chất lượng của sản phẩm và trải nghiệm người dùng.

Phase 2 sẽ xây dựng dựa trên nền tảng của Phase 1 với ollama_model.md và các RAG services đã implement. Các files mới cần tạo bao gồm detailed specs cho phase 2, ChatWidget components trong frontend, llm-judge.service.ts và evaluation.entity.ts trong backend. Trước khi bắt đầu Phase 2, chúng tôi cần review và test kỹ lưỡng Ollama integration ở Phase 1, tạo UI/UX mockups cho Phase 2, và setup frontend structure để sẵn sàng cho implementation.
